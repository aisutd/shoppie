## What works locally

The fixture coordinator runs saved HTML through the scraper, Pydantic validation,
the version 1 JSON envelope, normalization, local observation storage, reusable
MiniLM embeddings, hybrid search, and separate deal ranking. The dashboard and API
use the same backend service. The demo returns two exact synthetic M5/16GB/512GB
offers in total-price order and excludes incompatible hardware. Missing evidence
requires review. Conflicting manufacturer models/colors/sizes are not compared as
equivalent offers. Price and retailer data are never generated by a language model.

The existing MySQL importer/history schema and old Supabase public.products uploader
remain separate. PostgreSQL support is explicit and additive, with no auto migration.

## Verification evidence

`SHOPPIE_RUNTIME_TESTS=1 .venv-ai/bin/python -m pytest -q` passed **225 tests**.
This includes the original 195 tests and the added backend/runtime checks.
Real MiniLM inference produced 384 finite values with squared L2 norm approximately
1.0. Real Chromium rendered a controlled JavaScript page, stopped on a challenge,
and rejected a changed product URL. Requests redirect tests reject external hosts.
The Streamlit application test completed a two-retailer synthetic search.

`python -m compileall -q backend db scraper normalizer dashboard.py tests`,
`python -m pip check`, and `git diff --check` passed.
The running localhost /health, /products, /search, /deals, and /scraper/status
endpoints returned HTTP 200; /deals returned two exact synthetic offers. The local
dashboard was opened and visually checked.

The default pytest run skips the three runtime tests unless SHOPPIE_RUNTIME_TESTS=1.
The first restricted Chromium launch was denied by the execution sandbox; the
normal macOS-permission run passed. No retailer security protection was bypassed.

## Evaluation results and limits

The ten authored fixture pages yielded 10 readable files, 8 extracted records,
7 validation successes, and 3 rejections (challenge, missing price/currency, and
conflicting visible/JSON-LD price). Acceptance was 7/10. One accepted record lacked
labeled RAM evidence and remains manual review. Present labeled fields agreed
100/100, prices 7/7, and present model/variant record comparisons 8/8. Missing values
are counted separately; these ratios do not establish real-world reliability.
A test-only faulty extractor verifies that an incorrect price can be counted among
accepted records (1/7) rather than being mislabeled as failed extraction.

The real-model three-query synthetic search evaluation yielded Precision@2=1.0
for the two-offer M5 query and Precision@1=1.0 for each single-offer query. Macro
precision was 1.0 on this tiny labeled set only. It is not a general search benchmark.
Current timing and detailed denominators are generated by `python -m scraper.evaluate`;
JSON reports are in ignored `.local/` output. Timing excludes network access.
